# sk8s v2 Design

**Date:** 2026-10-10
**Status:** Draft for review
**Scope:** Ground-up rebuild of sk8s as version 2.0.0

## 1. Goals and non-goals

### Goals

- Run Python functions as Kubernetes Jobs with one-line ergonomics, aimed at
  **public adoption**: stable API, docs, CI, migration story.
- Preserve v1's defining property: **no resident control plane**. The cluster is
  the scheduler; jobs can submit jobs; a workflow is a Python function.
- First-class **detached workflows**: submit a workflow, close the laptop, walk
  away; reattach later from any machine.
- Results of any picklable type (not JSON-only), delivered reliably (never via
  pod logs).
- Clean, verified resource lifecycle: nothing leaks — jobs, ConfigMaps, PVCs,
  or store blobs.

### Non-goals

- No DAG engine, scheduler service, or cluster-resident operator.
- No workflow state/memoization layer (v1 `state.py` — cut).
- No Kafka/MongoDB deployment helpers (cut; `serve()` + docs cover the need).
- No terminal dashboard/kubewatch (cut).

## 2. Package architecture

Fresh codebase in this repo, version 2.0.0; v1 frozen on a `v1` branch and
installable as `sk8s<2`.

```
sk8s/
  api.py          # run, submit, map, submit_map, starmap, submit_starmap,
                  # submit_workflow, attach, serve, get_service
  cluster.py      # Cluster: holds config, builds jobs, returns Futures
  future.py       # JobFuture, WorkflowHandle
  spec.py         # builds V1Job / V1Deployment etc. via kubernetes client models
  store/          # BlobStore interface; configmap.py, s3.py, gcs.py, local.py
  serialize.py    # payload/result/exception (de)serialization + version header
  watch.py        # shared per-process watch on Job events -> resolves futures
  volumes.py      # PVC create/delete, scratch_volume context manager
  services.py     # function -> Deployment + Service
  images.py       # Dockerfile templating, build, push
  config.py       # typed layered config
  cli.py          # `sk8s` console entrypoint
  errors.py       # RemoteException, PodFailed, ImagePullError, JobTimeout, StoreError
  worker.py       # in-pod entrypoint: fetch payload, run, store result
  local.py        # LocalCluster: subprocess backend, same interface as Cluster
```

Design rules:

- **Kubernetes API client only.** No `kubectl` shell-outs, no Jinja-templated
  YAML, no `shell=True` anywhere in the core. (kubectl survives only as a
  convenience inside `sk8s shell`.)
- **Job specs never carry code.** Payloads travel through the BlobStore; specs
  are small and constant-size.
- **Watch, don't poll.** One shared watch per process resolves futures; no
  1-second polling loops; no pandas dependency.
- Full type hints, `py.typed`, `mypy --strict` in CI.

### Lifecycle of `sk8s.submit(f, x)`

1. `serialize.py` pickles `(f, args, kwargs)` with cloudpickle; `store` writes
   the payload blob, returning a URI.
2. `spec.py` builds a `V1Job`: fixed entrypoint `python -m sk8s.worker`, the
   payload URI as an env var, labels `sk8s/workflow-id` and `sk8s/parent-job`,
   `ttlSecondsAfterFinished` set, owner reference to the workflow anchor.
3. `cluster.py` submits via the API client; returns a `JobFuture`.
4. In the pod, `worker.py` fetches the payload, checks the version header, runs
   the function, writes the pickled result — or pickled exception + traceback —
   to the store.
5. `watch.py` sees the Job complete, fetches the result blob, resolves the
   future (re-raising remote exceptions with remote tracebacks).

Jobs-submitting-jobs is unchanged from v1: the worker image contains sk8s,
in-pod detection selects in-cluster config, and the service account's RBAC
permits creating Jobs/ConfigMaps/PVCs.

## 3. API

### Module-level functions (the primary surface)

```python
import sk8s

res = sk8s.run(f, x)                 # blocking one-liner == submit(f, x).result()
fut = sk8s.submit(f, x)              # -> JobFuture
res = fut.result(timeout=600)

results = sk8s.map(g, data)          # blocking, ordered list
futs    = sk8s.submit_map(g, data)   # -> list[JobFuture]
# starmap / submit_starmap mirror map / submit_map

gpu = sk8s.Cluster(image=img, limits={"nvidia.com/gpu": 1})   # scoped config
fut = gpu.submit(train, data)
```

Module functions delegate to an implicit default `Cluster` (the `requests`
default-Session pattern). No executor ceremony required for the common path.

### JobFuture

A `concurrent.futures.Future` subclass: `result(timeout)`, `exception()`,
`done()`, `add_done_callback()`, and stdlib `as_completed`/`wait` all work.
Extras: `.job_name`, `.logs()`, and `.cancel()` — documented as stronger than
stdlib semantics: it deletes the Job even after it starts running.

### Fan-out control

- `batch_size` (default 1): packs N calls into one Job, with per-item
  results/exceptions. Replaces v1's `chunked_map`/`chunked_starmap`.
- `max_concurrent`: client-side cap on in-flight Jobs for quota-limited
  clusters.

### Per-call job options

`image`, `requests`, `limits`, `volumes`, `timeout`, `backoff_limit`,
`service_account`, `namespace`, `name_prefix`, `privileged`, `keep_results`,
`batch_size`, `max_concurrent`.

### Errors

- User-code exceptions are pickled by the worker; `future.result()` re-raises
  the **original exception type** with a `RemoteTraceback` chained in, so
  `except ValueError:` works across the cluster boundary.
- Infrastructure failures raise typed exceptions with actionable messages:
  `PodFailed(reason="OOMKilled", logs=...)`, `ImagePullError`, `JobTimeout`,
  `StoreError`, `VersionMismatch`.
- A failed `map` raises a summary (first exception + success/failure counts);
  `submit_map` allows per-item harvesting.

### Config

Frozen `Config` dataclass, layered resolution:
defaults < `~/.config/sk8s/config.toml` < `SK8S_*` env vars < `Cluster(...)`
kwargs < per-call kwargs.

Workers receive an explicit, minimal config (store URI, image prefix,
namespace) — never a repr of the whole client config.

## 4. Data plane

### BlobStore interface

Three methods: `put(key, data: bytes) -> uri`, `get(uri) -> bytes`,
`delete_prefix(prefix)`. Backends:

- **`k8s` (default):** ConfigMap-backed. Zero setup; works on minikube, Docker
  Desktop, GKE, EKS out of the box. ~1MB per-object cap — oversize errors say
  exactly how to switch backends.
- **`s3://`** (`pip install sk8s[s3]`) and **`gs://`** (`sk8s[gcs]`): unlimited
  size; recommended beyond ~1k concurrent jobs and for detached workflows.
  boto3 / google-cloud-storage are **quarantined** inside `store/s3.py` /
  `store/gcs.py` (~50 lines each); no other code imports them. Workers
  authenticate via IRSA (EKS) / Workload Identity (GKE), never baked-in keys.
- **`local`:** directory-backed, used by `LocalCluster` and unit tests.

Store choice is one config value (`store = "k8s"` or a URI prefix),
overridable per Cluster.

### Serialization

- **cloudpickle** (ecosystem standard — Ray/Dask/Spark), replacing dill.
- Payload = cloudpickle of `(func, args, kwargs)`; result = cloudpickle of the
  return value or exception. Any picklable result type round-trips.
- Payload header carries sk8s version, cloudpickle version, Python
  major.minor. Worker verifies before unpickling; mismatch produces a clear
  "client is 3.12 / image is 3.11 — rebuild with `sk8s image build`" error.
- Published worker images ship per Python minor (3.10–3.13); the client
  auto-selects the matching tag.

## 5. Workflows, anchors, and cleanup

### The anchor pattern

On first submission, the client creates one **workflow anchor** ConfigMap.
Every Job, payload ConfigMap, result ConfigMap, and workflow-created PVC —
including those created by nested jobs, which inherit the workflow id — holds
an owner reference to the anchor. Consequences:

- `sk8s kill <wf>` = delete one object; cascade delete removes everything.
- `sk8s clean` = list anchors, delete stale ones.
- Normal client exit = delete the anchor (`atexit` backstop).

Object-store blobs can't carry owner references; the anchor records the store
prefix, and whoever deletes the anchor also issues `delete_prefix`. Bucket
lifecycle rules (offered by `sk8s config`, default 7-day expiry on the sk8s
prefix) are the backstop.

### Detached workflows

```python
wf = sk8s.submit_workflow(pipeline, samples)   # driver runs in-cluster as a Job
print(wf.id)                                   # "wf-7f3ka" — walk away

# later, from any machine:
wf = sk8s.attach("wf-7f3ka")
wf.status()        # running / succeeded / failed, child job counts
result = wf.result()
```

- The **driver job is the per-workflow controller**: it supervises children
  while alive, and its normal result-fetching deletes intermediate blobs
  eagerly and in-cluster. Only the final result persists after it exits.
- CLI: `sk8s workflows`, `sk8s logs <wf>`, `sk8s kill <wf>`.
- `submit_workflow` warns when the default `k8s` store is in use (final result
  capped at ~1MB and may wait days to be fetched; object store recommended).

### Cleanup rules (no lease, no controller pod)

- **Payloads** never outlive their Job: ConfigMap payloads are owner-referenced
  to the Job; object-store payloads are deleted when the future resolves.
- **Results** live until fetched (deleted on successful `result()` unless
  `keep_results=True`), killed, or past **retention age** after completion
  (default 7 days, configurable).
- Retention sweeping: `sk8s clean [--older-than ...]`, the worker-side
  opportunistic sweep (each worker deletes expired sk8s-labeled resources in
  its namespace before starting — one labeled LIST per job, no controller),
  and bucket lifecycle rules.
- A crashed interactive client leaves a workflow indistinguishable from a
  detached one; it ages out. One model covers both.
- Invariant (documented and integration-tested): payloads never outlive their
  Job; results live until fetched, kept, or expired — whichever comes first.

## 6. Services

```python
svc = sk8s.serve(func, name="model-server", port=8080)
svc.url        # http://model-server.<ns>.svc:8080
svc.logs(); svc.scale(n); svc.delete()
svc = sk8s.get_service("model-server")   # reattach
```

- Function is expected to run forever (e.g. start Flask).
- Deployment + Service built via client models; payload via the store; same
  labels/anchor integration so `sk8s clean` sees them.
- **Exempt from retention age** — services persist until explicitly deleted.

## 7. Volumes

- `create_volume(size, access_modes=...)` / `delete_volume(name)`, auto-mount
  at `/mnt/<name>`, rebuilt on the API client.
- Volumes created inside a workflow are owned by the anchor (die with it);
  `keep=True` opts out for data that outlives the workflow.
- `scratch_volume(size)` context manager for temp shared storage.

## 8. Images

- **Official published base images** on a public registry
  (e.g. `ghcr.io/jared-maguire/sk8s:<version>-py<minor>`), published by CI on
  release, version-locked to the PyPI package.
- Base = `python:3.X-slim` + sk8s + cloudpickle. No miniconda foundation, no
  gcloud SDK, no awscli, no kubectl (store backends use libraries, not CLIs).
- `sk8s image build [--conda ...] [--pip ...] [--push]` (and
  `sk8s.images.build()`) layers user deps on the official base; conda is an
  option for scientific stacks, not the foundation.

## 9. Cluster configuration

v1's cluster setup was scattered (three divergent `clouds/*.py` code paths, a
standalone `gke_rbac_config.sh`, loose YAML files, nothing idempotent or
checkable). v2 centralizes it:

### ClusterProfile

A typed, declarative description of everything sk8s requires from a cluster:

- Namespace and ServiceAccount.
- One **namespace-scoped Role** with exact verbs on jobs, pods, pods/log,
  configmaps, persistentvolumeclaims, deployments, and services —
  never cluster-admin. One RoleBinding.
- RWX storage class for volumes.
- Image registry strategy (prefix, auth model).
- Store binding (which BlobStore, and the identity binding workers use to
  reach it).

**Provider adapters** (`local`, `gke`, `eks`, `generic`) supply only
*parameters* — storage class names (Filestore / EFS), registry prefixes
(Artifact Registry / ECR), and the IAM steps for Workload Identity / IRSA.
The apply logic is shared; there are no per-cloud code paths that can drift.

### sk8s config — plan/apply

- Detects the provider from the kube context (overridable with `--provider`).
- Prints the full plan: Kubernetes objects it will apply (via the API client)
  and cloud-side IAM commands (`gcloud` / `aws`) it will run — with
  confirmation, or printed only under `--dry-run`.
- **Idempotent**: re-running converges to the profile; safe to run anytime.
- Offers the store bucket lifecycle rule (§5) as part of setup.
- Writes the resolved client config (provider, namespace, store, image prefix)
  so the runtime never re-detects.

### sk8s doctor

Verifies each profile requirement individually — cluster reachable, RBAC
verbs present, image pullable, store writable, storage class exists — and
prints pass/fail with the specific fix per item. `config` and `doctor` are
mirror images of the same ClusterProfile, so setup and diagnosis cannot
drift apart.

## 10. CLI

Console entrypoint `sk8s` (pyproject script, replacing `python -m sk8s`):

```
sk8s config [--store s3://...] [--provider ...] [--dry-run]
sk8s doctor
sk8s image build|push
sk8s workflows | logs <wf> | kill <wf> | clean [--older-than ...]
sk8s shell [--image ...]         # interactive pod (kept from v1)
```

## 11. Testing

Four tiers:

1. **Unit (no cluster):** spec building, serialization round-trips, config
   layering, store logic against fakes, error mapping. Plus `mypy --strict`.
2. **LocalCluster:** subprocess backend + `local` store; same interface as
   `Cluster`. Doubles as a shipped feature ("develop locally, point at k8s
   unchanged"). The full API test suite runs against it in seconds.
3. **Integration — minikube (per-PR):** the suite runs against whatever
   cluster the kube context points at, with **minikube as the reference
   environment**, locally and in CI (GitHub Actions `setup-minikube`;
   minikube's registry addon serves the local-image path). Covers jobs,
   fan-out, detached workflows, volumes, services, failure injection (OOM,
   bad image, worker exceptions), and **cleanup verification: every test
   asserts nothing is left behind**. S3 paths tested against in-cluster MinIO.
4. **Integration — GKE + EKS matrix (nightly and on release tags):** GitHub
   Actions authenticates via OIDC federation (no stored cloud keys) and
   creates an **ephemeral cluster per run** (GKE Autopilot; EKS via eksctl).
   Each run executes `sk8s config` against the fresh cluster — making
   first-run setup a tested invariant, which v1 could never verify — then the
   full suite with real GCS/S3 store backends and cleanup assertions, then
   tears the cluster down. Ephemeral-per-run costs ~20 min of spin-up per
   cloud but avoids the drift and silent coverage loss of a persistent test
   cluster.

## 12. Packaging and release

- `pyproject.toml`; core deps: `kubernetes`, `cloudpickle` only.
  Extras: `sk8s[s3]`, `sk8s[gcs]`. Python 3.10–3.13.
- Removed from runtime deps: pytest, flask, pymongo, pandas, jinja2, dill,
  pyyaml.
- Tag push → GitHub Actions publishes the PyPI package and the per-Python
  worker images with matching version tags.
- v1 frozen on a `v1` branch, installable as `pip install "sk8s<2"`.

## 13. Documentation

- README: short pitch + 5-minute quickstart (minikube/Docker Desktop path,
  zero cloud setup).
- `docs/`: GKE/EKS setup (including IRSA/Workload Identity for stores),
  detached workflows, store backends, custom images, and a **v1→v2 migration
  page** mapping every old call to its replacement.

## 14. v1 → v2 surface mapping

| v1 | v2 |
|---|---|
| `run(f, x, asynchro=False)` | `run(f, x)` |
| `run(f, x)` (async, returns job name) | `submit(f, x)` → `JobFuture` |
| `wait(job)` | `future.result()` |
| `map` / `starmap` | `map` / `starmap` (blocking) or `submit_map` / `submit_starmap` |
| `chunked_map` / `chunked_starmap` | `map(..., batch_size=N)` |
| `run(workflow)` as driver job | `submit_workflow(workflow)` → detachable handle |
| results via pod logs (JSON-only) | results via BlobStore (any picklable) |
| `RuntimeError("Jobs 0 1 0 ... failed")` | original exception re-raised w/ remote traceback; typed infra errors |
| `docker_build` / `docker_build_jobs_image` | `sk8s image build` / `images.build()` on published base |
| `python -m sk8s config-cluster/-gke/-eks` | `sk8s config` (auto-detect) |
| `services.py` mongo/kafka helpers | cut; `serve(func)` remains |
| `state.py` memoization | cut |
| dashboard / kubewatch | cut (`sk8s workflows` covers listing) |
