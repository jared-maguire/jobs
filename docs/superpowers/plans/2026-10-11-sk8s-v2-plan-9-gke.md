**Goal:** sk8s works on GKE end-to-end: a `gke` provider adapter, Workload Identity for the GCS store, Artifact Registry images, doctor checks that prove the *worker's* identity (not just the client's), the existing integration suites green against the real cluster, and a verified GKE guide.

**Ground truth (discovered 2026-10-11):** project `jared-genome-analysis`; cluster `autopilot-cluster-1` (us-central1, **Autopilot**, running, scaled to zero); `artifactregistry`/`container`/`file` APIs enabled; no sk8s AR repo or GCS bucket yet. Autopilot facts that bind this plan: Workload Identity enabled by default; Filestore CSI built in; **no privileged pods** (sk8s's `privileged=True` will be rejected by the API — expected, document); resource requests are mutated to Autopilot minimums (tests must not assert exact requests); scale-from-zero adds ~1–2 min to the first pod — all live timeouts sized accordingly.

**Spec:** `docs/superpowers/specs/2026-10-10-sk8s-v2-design.md` §4 (stores), §9 (adapters — previously tabled), §11 narrowed: **no recurring cloud CI in this plan** (nightly ephemeral-cluster CI stays parked until Jared opts into the recurring cost; this plan's verification is live-but-manual).

**Branch/workflow:** `feat/gke` from `version-2`, clone `~/code/jobs/jobs.gke`. PR into `version-2`; merge gate = the (local-CI) run plus the live-GKE evidence in task reports.

## Global Constraints

(All prior constraints carry: client models only, no shell=True, mypy --strict, TDD, suite green per commit. gcloud is sanctioned the way kubectl is: CLI/dev-docs/tests only, never the library.)

- The `gke` adapter supplies PARAMETERS only (the shared apply logic is untouched): `profile_for("gke", *, project, region, namespace, store, repo="sk8s", gsa=None)` → image_prefix `f"{region}-docker.pkg.dev/{project}/{repo}/"`, rwx_storage_class `"standard-rwx"`, and a ServiceAccount annotation `iam.gke.io/gcp-service-account: <gsa>` when a GSA is given (Workload Identity).
- `detect_provider()` recognizes `gke_<project>_<location>_<name>` context names.
- Cloud-side IAM is **plan-first**: `sk8s config --provider gke` prints the exact `gcloud` commands (GSA create, `roles/storage.objectAdmin` on the bucket, `roles/iam.workloadIdentityUser` binding, `roles/artifactregistry.reader` for nodes if needed) and runs them only under `--apply-cloud`; `--dry-run` prints everything. The Kubernetes objects apply exactly as today.
- Doctor gains the carried worker-identity check: when the cluster is reachable AND the store is `gs://`, an **in-cluster probe job** does a store write/read/delete from a pod and reports PASS/FAIL with WI-specific hints. Client-side store probing alone must never report a `gs://` store healthy on GKE.
- Costs stay visible: anything this plan creates in GCP is named `sk8s-*`, listed in the task report, and torn down unless it's part of the durable setup (AR repo, bucket, GSA). Filestore RWX is the expensive one (basic tier has a 1 TiB minimum) — the RWX volume test is opt-in via `SK8S_GKE_RWX=1`, creates late, deletes immediately, and documents the cost.

## Review Focus

1. The in-cluster identity probe must fail loudly and diagnosably when WI is misconfigured (the single most common GKE setup failure) — pinned by a live red-then-green in Task 2.
2. Autopilot request mutation must not break any assertion — audit every test the GKE run reuses for exact-resource expectations.
3. Nested jobs on GKE (jobs-submitting-jobs) must inherit everything they need with a `gs://` store and WI — the carried P3 item, finally testable for real.
4. `privileged=True` on Autopilot: a typed, actionable error (surface the API rejection well), not a hang.
5. The guide's walkthrough must be executed verbatim on the real cluster, like every doc before it.
